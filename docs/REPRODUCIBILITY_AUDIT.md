# K3 源码与教程复现审计（2026-10-29）

主入口：[从零构建与 RFsim 复现](../tutorials/reproduction/README.md)。本次在现有 K3 上建立独立源码、依赖、构建和结果目录，保留原部署与原始实验数据。不是重装操作系统，也没有重新验收真实射频或核心网端到端业务。

## 核对发现与修复

| 原来的缺口 | 本次处理 |
|---|---|
| 旧教程 OAI `207aac9`，现场为 `c6698f7` | 新主线直接使用固定 vendor 树和现场 overlay；旧教程标出历史基线 |
| 系统 SIMDe 有六个未发布的头文件修改 | 发布原差异及 SHA256，固定上游提交并安装在私有目录 |
| ASN1C 来自本机 `/opt`，新机无法照搬 | 固定源提交，构建工作区私有 ASN1C |
| RFsim 构建脚本仍强制 USRP/UHD | 修正原辅助脚本，仅 `--usrp` 构建设备插件；新主线明确关闭 USRP |
| 旧实验脚本全局停止同名进程、固定服务名 | 新 runner 每轮创建独立 namespace，只清理自己 namespace 内的进程 |
| 累计均值容易被误当窗口指标 | CSV 明示差分估计与累计最大值，保存起止原始快照及观察时间 |
| 只检查补丁应用，未验证构建/同步 | 新增源码完整性、依赖、产物散列、动态库、实际同步和计数增长门禁 |
| Release 与源码核心网路径混用，缺少订阅步骤 | 补充布局、网络参数、测试卡本地插入工具、UHD 和分级验收 |

## 本次实际验证

- 现场 Ubuntu 26.04.1 / riscv64、内核 `6.18.3-k3-sctp+`、GCC 16.0.1；原项目 HEAD 为 `0abdce3`，OAI HEAD 为 `c6698f7`。现场其余状态见 [只读核查记录](K3_CURRENT_STATUS.md)。
- 全新隔离源码准备：3,953 个源文件/链接与手工独立准备的同基线逐项比较通过。仓库历史 CRLF blob 与 LF checkout 的差异仅按声明的文本类型规范化，其他内容变更仍拒绝。
- 使用现场已有 ASN1C/SIMDe 完成首次干净构建，六个目标成功；`ldd` 与产物散列检查通过。
- 首次 ideal RFsim 功能测试通过：gNB 监听、nrUE 同步、双方计时计数增长；原始日志、配置、起止快照与 CSV 留在 K3 隔离结果目录。
- 固定提交的 SIMDe 与 ASN1C 已独立下载、校验、构建到私有目录；六个修改后的 SIMDe 头文件与现场逐字节一致。使用新脚本、私有 ASN1C/头文件及 RVV 参数完成 10,833 项全量构建，六个目标、动态依赖与产物散列检查通过。CMake 编译器缓存变化会丢失设置的问题已加失败停止检查。
- 私有依赖构建的 ideal/AWGN 功能对照于 17:26:22–17:26:54（Asia/Shanghai）完成：各一轮、2 秒预热、4 秒观察、CPU 2–7、106 PRB；两轮均同步成功且双方计数增长，各保存 67 行窗口统计。结果标记 `functionalOnly=true`，后台核心网保留，不作为空闲主机性能数据。
- K3 上 19 项离线检查全部通过；订阅工具的只读 schema 检查通过，没有读取或写入订阅密钥。原部署守卫仍通过 39 项文件检查。

## 验证边界

本次不会为性能测量停止正在使用的核心网。正式 ideal/AWGN 五轮应在空闲主机依照教程执行；短时功能测试不构成性能结论。x86/ARM64、从全新 OS 开始的 apt 安装、CN5G Release 全新安装、SIM/真实 UE、B210 射频与 AI 实时吞吐未在本次重新验收。相应教程列出必须通过的门槛，不把已有机器状态或静态检查写成全平台通过。

所有新结果写到隔离工作区，旧数据不移动、不覆盖。公开仓库只提交脚本、依赖差异、版本和本审计；本地密钥、数据库、设备身份、配置与运行日志不上传。
