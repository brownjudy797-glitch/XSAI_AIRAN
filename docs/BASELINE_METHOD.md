# Baseline 实验方法：RFsim、真实 UE 与 AI 对照

本文从早期 K3 RFsim 热点、B210 真实 UE、x86/ARM 对照指导中提炼**仍适用的方法**。它是实验设计与记录指南，不是新机器的一键启动脚本。第一次连接真实 UE，请先按 [Quickstart](../tutorials/quickstart/README.md) 完成接入检查；部署与目录说明见 [K3 使用指南](K3_PROJECT_GUIDE.md)。

## 先选对基线

| 类型 | 测什么 | 不证明什么 |
|---|---|---|
| RFsim PHY 基线 | 固定配置下的 OAI 模块热点、算法数值与调用次数 | B210/USB、真实空口、UE 和公网性能 |
| B210 + UE 端到端基线 | 注册、PDU 会话、本地用户面、吞吐、丢包、RTT 和稳定性 | 某个 PHY 函数本身的耗时归因 |
| AI/传统 A/B | 同一硬件、负载和 RB 条件下，传统路径与指定 AI 插件的效果 | 不同 RB、不同平台或不同链路条件下的直接“加速比” |

不要把旧 x86/ARM/K3 的 **106 PRB RFsim** 热点结果与当前 **24 RB B210** 实机结果直接相除。RFsim 与真实空口、载波 RB 上限与每次动态调度 RB 也要分别标注。接收机当前只支持不超过 24 RB 的特定 16-QAM/DMRS 输入；发生传统路径回退时，不能将该样本记作 AI 推理。

## 每轮先记录条件

记录项目/OAI 提交、gNB 二进制与模型 SHA-256、内核/UHD/CN5G 版本、实际 gNB 配置、SCS/TDD、载波 RB 上限、**每次实际调度的 RB 分布**、MCS、B210 USB 速率与射频连接、UE/USIM、CPU 绑核、频率策略和测试方向。比较 AI 时另记插件 `.so` 路径、权重路径、加载日志与真实调用计数；只看到 CPU8 占用不等于证明 AI 被调用。

配置、身份和网络地址以现场读取为准。公开结果只放脱敏摘要，不提交 SIM/订户信息、数据库、原始核心网日志或含设备身份的抓包。射频实验仅在获准环境进行。

## 推荐执行顺序

1. **预检**：核对固定版本、B210 USB 3.0、服务数量与健康状态；确认 UE 已注册、PDU 会话存在并获得业务地址。运行中的系统不要为“刷新日志”反复重启。固定快照的 `scripts/k3-fixed-baseline.py --check` 只适用于已创建该快照的 K3，不是新机器的通用验收命令。
2. **本地冒烟**：在 Windows 查实际 UE 网卡和地址，绑定该源地址 Ping 本地 UPF（本实验常用 `12.1.1.1`，现场可能不同）。先验证 10 秒左右的本地路径，再谈公网或直播；不指定 UE 源地址可能误走 Wi-Fi。
3. **空闲/轻载基线**：先预热，再记录一段稳定窗口的 Ping、服务状态、线程与 OAI 计时。不要把一次 Ping 成功写成长时间稳定。
4. **阶梯负载**：上下行分开，用相同包长、独立窗口逐档提高目标速率；记录**接收端**吞吐、丢包和抖动，而非只记 iperf 发送目标。每档前后确认 UE 地址、PDU 会话及服务实例未变。旧指导以 1200 字节 UDP、100K/250K/500K/1M/2Mbit/s 为起始阶梯；这只是实验方案，不是标准或当前系统上限。
5. **A/B 对照**：传统路径先跑完整轮，再只改变一个因素（例如启用接收机），用同样的 RB/MCS、无线连接、流量、绑核和窗口重复。先做 3 轮摸底，正式比较建议各 5 轮；候选速率还要单独做较长稳定性测试。旧指南的“预热 60 秒、测量 120 秒、档间 30 秒、最终 30 分钟”可作为起点，若调整必须在两组中一致记录。

仓库的 `scripts/run-k3-hotspot-experiment.sh` 属于 **RFsim 专用**，会停止已有 OAI 进程以隔离实验；不能在在线 B210 gNB/核心网旁直接运行。`scripts/run-k3-e2e-collector.sh` 只是 K3 侧采集器，不是完整的 Windows 业务控制器。不要把旧工作区中的控制脚本名称写成当前仓库可直接运行的命令。

## 数据有效性与报告

gNB/核心网重启、UE 地址变化、PDU 会话中断、iperf 错误或采集窗口不完整时，该轮标为 `INVALID` 并保留原始证据；不要填成 0 Mbps，也不要从失败统计中删除。报告有效轮数/总轮数、失效原因、均值和尾部/离散程度。短阶梯通过不等于 30 分钟稳定，更不等于更高 RB 已适配。

至少保存：时间与标签、代码/二进制/权重哈希、实际配置、服务实例、UE 地址状态、方向/包长/目标速率、接收端吞吐/丢包/抖动、RB/MCS 分布、OAI 计时快照、AI 调用与回退计数，以及异常日志的脱敏摘要。基础接入可使用 [Quickstart 验收模板](../tutorials/quickstart/acceptance-template.md)；吞吐实验需另附每档原始 iperf 结果。

## PHY 耗时怎么比较

OAI 的统计常是进程启动以来的累计平均值。若起点/终点的调用数为 `N0/N1`、平均耗时为 `A0/A1`，且期间**没有重启或清零**，则同一测量窗口的平均耗时近似为：

```text
窗口调用数 = N1 - N0
窗口平均耗时 = (A1 × N1 - A0 × N0) / (N1 - N0)
```

必须检查 `N1 > N0`、计时单位一致、两次快照完整；打印精度会带来近似误差。嵌套计时不能相加，终点累计最大值也不是窗口最大值。传统 PHY 与 AI 插件要按相同 PUSCH 范围定义是否包含共同的信道估计；单看 `top`、`pidstat` 或 `perf` 不能代替 OAI 模块计时。详细插件时间点见 [AI 插件接入与观察](AI_PLUGIN_INTEGRATION.md)。
